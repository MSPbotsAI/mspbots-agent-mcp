## 需求理解

一句话：把 Usage 页那个概览接口（含每个 agent 的花费/运行次数、以及创建人邮箱与创建时间）包成 MSPbots Agent Platform MCP 下的一个只读工具。

复述：提单方已经把接口契约写全了（`GET /api/usage/overview`，7 个可选查询参数、200 的完整响应形状、
两种错误、以及建议的工具名 `mspbotsagent_get_usage_overview`）。要做的是在本仓加一个 1:1 的包装工具：
转发调用方的 `Authorization`、把参数原样带过去、把响应 JSON 交回给模型，其中 `debug` 可以剥掉，
但 `spendUnavailable` / `spendTruncated` 必须原样透传。成功的样子是：一个 agent 能回答
「我们这周花了多少、哪个 agent 花得最多、这些 agent 是谁建的」，并且在花费读不到时说「读不到」而不是「0」。

## 现状（每条断言带 path:line）

### 一、本仓已经把工单担心的三件事解决了

工单强调了三个包装器要注意的点，逐条对下来都已经是现成行为（`e45ded6` 实读）：

1. **挂载前缀** —— 工单说外部包装器必须用「部署 origin + `/apps/{app}/` 前缀」。
   `src/mspbots_agent_mcp/api_client.py:13` 有 `_APP_PREFIX = "/apps/mb-platform-agent"`，
   `:83` 用 `host.rstrip("/") + _APP_PREFIX` 拼 `_base_url`，`:123` 再拼上传入的 `path`。
   **工具里只写 `/api/usage/overview` 即可。**
2. **转发调用方的 token** —— `api_client.py:87` 固定发 `Authorization: Bearer {self._token}`，
   token 来自 `server.py` 的 contextvar 隔离（`server.py:83` 起的 `client_factory`），一次调用一份凭据。
   **AC4 要的「原样转发、不用服务账号」已经成立**，不需要在本单里做任何事。
3. **非法值回落默认** —— `api_client.py:93-96` 的 `_clean_params` 把值为 `None` 的参数整条丢掉。
   所以包装器**不传**未指定的参数，服务端自己取默认值。**AC3 的「非法值回落而不是报错」天然成立**，
   不需要在包装器里重写一遍校验（重写反而会和服务端的口径漂移）。

### 二、工具的写法在本仓是定型的

`src/mspbots_agent_mcp/tools/connectors.py` 是最贴近本单的样板（只读、零参、走一个 GET）：

- 每个模块导出 `register(mcp, client_factory)`；`server.py:118` 一行 import、`:120-125` 一行调用。
- 只读工具标 `@mcp.tool(annotations=ToolAnnotations(readOnlyHint=True))`（`connectors.py:13`）。
- 拿不到凭据返回 `_common.NO_TOKEN`（`tools/_common.py`，内容是一条 `not_configured` 的 error envelope）。
- 上游报错走 `except AgentError as e: return e.to_envelope()`（`api_client.py:62-64`，按状态码分类并标 retryable）。
- 返回值用 `_json.dump_json_capped(...)`。

### 三、两处必须在设计里处理的坑（本单新发现）

**坑 1 · 输出有 20000 字符上限，而 `pageSize` 最大 1000。**
`_json.py:11` 的 `MAX_CHARS = 20_000`，`dump_json_capped` 超限时**截断最大的那个 list 字段**
（`_json.py:18-30`）。本接口的 `breakdown` 一行有 10 个字段，`pageSize=1000` 时轻松超过 2 万字符 ——
**会被静默截掉一部分行，而 `breakdownTotal` 仍然报全量**，模型据此会以为自己看全了。
这是本单唯一需要在包装器里加逻辑的地方，见技术设计 3。

**坑 2 · 界面说的是「credits」，接口说的是「USD」。**
`ProductDocs/16-Usage.md:29` 记着 KPI 磁贴是 **CREDITS USED / TASKS**，原文「Spend is denominated in credits」；
`:31` 记着 Breakdown 的列名是 **AGENT / MODEL LAST USED / CREDITS / TASKS**（_verified_ 2026-08-12, v4.1.292）。
而工单的响应契约里写的是 `totalSpend`（USD）、`cost`（USD）、`runs`。同一份数据在界面上叫 credits，
在接口里叫 USD；界面的 TASKS 对应接口的 `runs`；接口还返回一个界面上**已经没有磁贴**的 `threads`
（`16-Usage.md:29`：THREADS 磁贴在 v4.1.408 被移除）。

**为什么这条重要**：工具的 `description` 是给模型读的。若写「total spend (USD)」，模型会答
「你们花了 12.34 美元」，而用户在 Usage 页上看到的是「185.06 credits」——两个数字对不上，用户会当成 bug。
处置见 OQ-1（已带假设推进，不阻塞）。

## 产品设计

### 目标

- **G1** 一个 agent 能用自然语言问出租户的用量：一段时间内的总花费、运行数、agent 数，
  按 agent 的明细（花费/运行数/模型），以及每个 agent 的创建人与创建时间。
- **G2** 花费读不到时，agent 说得出「读不到」而不是报 0。
- **G3** 数据严格按调用者自己的租户返回，不出现跨租户。

### 非目标

- **N1 不做 `GET /api/usage/agent/{agentId}/runs` 的单 agent 下钻**（工单已明确划为范围外，
  以后可以是第二个工具 `mspbotsagent_get_agent_usage_runs`）。
- **N2 不改 mb-platform-agent** —— 接口已经存在，本单只做包装（工单原话）。
- **N3 不在包装器里重算或校正任何数值**（不做 USD↔credits 换算，见 OQ-1）：包装器要么原样透传，
  要么明确说明，绝不自己算 —— 算错一个数比不算严重得多。

### 验收标准

**AC1** Given MSPbots Agent Platform MCP 已装载本次改动，When 列出工具，
Then 存在一个名字带 `mspbotsagent_` 前缀且表达 `usage_overview` 意图的工具，
标注为只读（`readOnlyHint`），且没有必填参数。

**AC2** Given 调用方带着有效的平台 token，When 不传任何参数调该工具，
Then 返回的 JSON 与 `GET /api/usage/overview` 对同一用户的响应一致（默认 `7d` / 第 1 页 / 10 行 / cost desc）。

**AC3** Given 同一调用方，When 分别传 `range` / `page` / `pageSize` / `sortBy` / `sortOrder` / `sopId` / `source`，
Then 每个参数都被转发且结果可观察地变化；传非法值（如 `range=xx`、`sopId=-1`）时**不报错**，
而是回落到服务端默认值。

**AC4** Given 未提供凭据，When 调该工具，Then 返回 `not_configured` 的 error envelope；
Given 提供了无效 token，Then 返回上游 `401 UNAUTHENTICATED` 对应的 envelope，**不是**包装器自己的通用错误。

**AC5** Given 目标部署包含 mb-platform-agent 的提交 `08745928`，When 调该工具，
Then `breakdown[]` 的每一行都带 `createdBy`（邮箱，或解析不出时的 UUID 原值）与 `createdAt`（ISO 字符串或 `null`），
且 `deleted: true` 的行这两个字段为 `null`。

**AC6** Given 上游返回 `spendUnavailable: true` 或 `spendTruncated: true`，When 调该工具，
Then 这两个布尔值**原样出现在**工具返回值里（不被改写、不被吞掉）。

**AC7（本单新增，对应坑 1）** Given `pageSize` 大到让响应超过输出上限，When 调该工具，
Then 返回值**不得**出现「行被悄悄截掉但 `breakdownTotal` 仍报全量」的状态：
要么行数完整，要么返回值里有一个明确的标记说明被截断了多少行。

**AC8（本单新增）** Given 上游返回了 `debug` 字段，When 调该工具，
Then 返回值里没有 `debug`（按工单建议剥掉），而其余字段一个不少。

### Open Questions

- **OQ-1（已带假设推进，不阻塞）· 工具描述里的金额单位怎么说。**
  接口叫 USD，界面叫 credits（`16-Usage.md:29`，_verified_ 2026-08-25）。
  **本设计的假设**：字段名一律沿用接口原名（`totalSpend` / `cost`），并在工具 `description` 里明写
  「数值与 Usage 页的 CREDITS 列同源，页面以 credits 计价」，**不做任何换算**（N3）。
  若产品要求工具直接报 credits，需要先确认换算率的权威来源在哪 —— 那时要重做技术设计的返回值一节。
- **OQ-2（不阻塞）· `threads` 要不要留。** 接口返回它，但界面在 v4.1.408 已移除 THREADS 磁贴。
  假设：**原样透传**（少一个字段对模型没坏处，砍掉则可能让「有多少会话」这类问题无法回答）。
- **OQ-3（必答，但属于环境而非代码）· AC5 的验证环境。**
  `08745928` 在 mb-platform-agent 的 `kaka-new-thread` 分支上。**要先确认它已经进了 MCP 容器实际打到的那个部署**
  （`release-aks` / `INT`），否则 `createdBy` / `createdAt` 在响应里根本不存在，AC5 无从判定。
  这条不阻塞设计与实现，但**阻塞 AC5 的验收**。

## 技术设计

### 改动清单

1. **新增 `src/mspbots_agent_mcp/tools/usage.py`** —— 照 `tools/connectors.py` 的形状：
   ```python
   def register(mcp: FastMCP, client_factory: Callable[[], AgentClient | None]) -> None:
       @mcp.tool(annotations=ToolAnnotations(readOnlyHint=True))
       async def mspbotsagent_get_usage_overview(
           range: str | None = None, page: int | None = None, pageSize: int | None = None,
           sortBy: str | None = None, sortOrder: str | None = None,
           sopId: int | None = None, source: str | None = None,
       ) -> str:
   ```
   全部参数**默认 `None`**（不是给默认值）——这样 `_clean_params`（`api_client.py:93-96`）会把没传的整条丢掉，
   服务端取自己的默认值，AC3 的回落语义由服务端唯一持有。
   函数体：`client = client_factory()`；`None` → `return NO_TOKEN`；
   `await client.get("/api/usage/overview", params={...})`；
   `except AgentError as e: return e.to_envelope()`；成功后按第 3 条处理再 `dump_json_capped`。
   **docstring 是给模型读的**，照本仓风格写「什么时候用它」+ 关键语义（分页是按 agent 不按时间、
   `range=all` 没有 `daily`、`spendUnavailable=true` 时必须说读不到、`createdBy` 可能是 UUID 不是邮箱、
   以及 OQ-1 那条 credits 说明）。
2. **`src/mspbots_agent_mcp/server.py:118` 与 `:120-125`** —— import 与 register 各加一行 `usage`。
3. **返回值整形（本单唯一的自有逻辑，对应坑 1 与 AC7/AC8）**：
   - 剥掉 `debug`（AC8）。
   - **在交给 `dump_json_capped` 之前自己判断**：若序列化后会超 `_json.MAX_CHARS`，
     就主动把 `breakdown` 截到能放下的行数，并加上 `breakdownReturned: <实际行数>` 与
     `breakdownTruncatedByToolOutput: true` 两个字段。**不能依赖 `dump_json_capped` 默认的截断** ——
     它会静默砍掉行且不留标记（`_json.py:18-30`），那正是 AC7 要禁止的状态。
     （另一种选择是在包装器里把 `pageSize` 硬上限压到能放下的值，但那会让 AC3「参数被原样转发」失真，
     所以选「照传、超了就明确标注」。）
4. **`tests/test_tools.py`** —— 在 `EXPECTED_TOOLS` 里加一行
   `"mspbotsagent_get_usage_overview": (set(), {"readOnlyHint"})`（必填参数为空集）。
   该文件的现有测试是「`tools/list` 快照 + 错误码映射」、**不打网络**（文件头 docstring），
   本单新增的整形逻辑要能被纯函数化地测到，所以把第 3 条抽成模块级函数（例如 `_shape_overview(payload)`）再单测。

### 契约

工具入参 → 查询参数 **1:1 同名转发**，不改名、不做别名。返回值是上游 200 的 JSON，
去掉 `debug`，可能多出 `breakdownReturned` / `breakdownTruncatedByToolOutput` 两个字段（仅在截断发生时）。
错误一律走本仓既有的 error envelope（`api_client.py:62-64` 的分类 + `_json.error_envelope` 的形状），
**不发明新的错误形状**。

### 非功能

- **多租户隔离**：租户来自调用方 token（`api_client.py:87` + `server.py` 的 contextvar 隔离），
  包装器**不接受任何租户参数**，也不落任何缓存。`sopId` 落在租户外时上游自然返回空范围（工单已说明）。
- **只读**：`readOnlyHint=True`，且只发一个 GET，不带 body。
- **输出预算**：见改动清单 3。上限来自 `_json.py:11`。
- **超时/重试**：沿用 `AgentClient` 现有行为，本单不改。
- **不记日志里的敏感信息**：本单不新增任何日志；token 与响应正文都不落日志。

### 风险

- **R1 `pageSize` 大值下的截断语义。** 若第 3 条没做，就会出现「模型以为看全了其实没有」——
  比报错更坏，因为它不可见。AC7 是防线。
- **R2 单位口径（OQ-1）。** 工具描述若只说 USD，agent 的回答会和 Usage 页的 credits 对不上。
  已按假设在 description 里说明，但这是产品口径问题，groom 上确认一下更稳。
- **R3 AC5 依赖环境（OQ-3）。** `08745928` 没进目标部署时，`createdBy` / `createdAt` 直接不存在，
  且**不会报错**——响应里少两个字段而已。所以 AC5 的验收必须先确认部署版本，否则会误判成实现漏做。

### 工作量

约 0.5–1 人日（含测试）。改动集中在一个新文件 + 一行注册 + 测试，没有跨仓依赖。
